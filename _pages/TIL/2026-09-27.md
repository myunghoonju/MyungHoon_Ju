**한 일**
- JDK 25 구조적 동시성(Structured Concurrency) 프리뷰 API로 여러 원격 호출을 병렬 fork/join하는 예제 작성 (`VirtualThreadApiController`, `InfoJoiner`)
- `ScopedValue`와 `ThreadLocal`을 같은 요청 안에서 같이 세팅해보고, 가상 스레드로 fork된 서브태스크에서 각각 어떻게 보이는지 비교 (`UserFilter`)

**배운 점**

- **`StructuredTaskScope`로 여러 서브태스크를 안전하게 fork/join**
  - `try (StructuredTaskScope<Object, Void> scope = open()) { scope.fork(...); scope.fork(...); scope.join(); }` 형태 — try-with-resources라 스코프가 닫힐 때 아직 안 끝난 자식(가상)스레드까지 정리됨
  - 기본 `open()`은 "하나라도 실패하면 나머지 서브태스크를 취소하고 예외를 던진다"는 전략(`talk`/`speaker` API에서 사용) — 여러 API를 동시에 부르되 하나라도 실패하면 전체를 실패로 처리하고 싶을 때 적합
  - `Joiner<T, R>` 인터페이스를 직접 구현하면 커스텀 join 전략도 가능. `InfoJoiner`는 구글/링크드인/페이스북 3곳을 동시에 호출하되, 페이스북 호출이 실패(`RuntimeException`)해도 무시하고 성공한 것들 중 정보량(`infolist().size()`)이 가장 많은 걸 리턴하도록 구현
  - `Joiner.onComplete(Subtask)`의 반환값은 "join을 여기서 조기 종료할지" 여부 — `true`면 남은 서브태스크를 취소하고 `join()`이 즉시 리턴, `false`면 전체가 끝날 때까지 계속 대기. `InfoJoiner`는 모든 결과를 다 모아야 하므로 성공/실패와 무관하게 항상 `false`를 반환
  - 프리뷰 API라 컴파일 타임뿐 아니라 런타임에도 `--enable-preview`가 필요 — `build.gradle`에서 `JavaCompile`/`JavaExec`/`Test` 태스크 전부에 `--enable-preview`를 추가해야 함. 컴파일만 켜고 실행 시(예: IntelliJ 자체 실행) 안 켜면 다시 프리뷰 관련 에러로 막힘

- **`ScopedValue`는 구조적 동시성의 자식 스레드까지 전파되지만 `ThreadLocal`은 안 됨**
  - `UserFilter`에서 요청 헤더의 `user` 값을 `ThreadLocal`과 `ScopedValue` 양쪽에 세팅해두고, `StructuredTaskScope.fork()`로 뜬 서브태스크(별도 가상 스레드) 안에서 두 값을 각각 조회
  - 결과: `ThreadLocal`은 `null` — 스레드가 다르므로 상속되지 않음. `ScopedValue`는 요청 헤더 값이 그대로 조회됨 — `ScopedValue.where(key, value).run(...)`으로 바인딩한 값은 fork된 자식 가상 스레드까지 안전하게 전파됨
  - 즉 요청 스코프 컨텍스트(로그인 사용자 등)를 가상 스레드/구조적 동시성과 함께 쓰려면 `ThreadLocal` 대신 `ScopedValue`를 써야 자식 태스크에서도 값을 읽을 수 있다는 걸 직접 로그로 확인
