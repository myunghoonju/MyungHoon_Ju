- 카프카 커넥트(Kafka Connect, distributed mode) 실습 — `FileStreamSinkConnector`로 `test` 토픽 내용을 파일로 읽고 쓰기
- `connect-distributed.properties` 설정으로 커넥트 워커 기동, REST API(`POST/GET/DELETE /connectors`)로 커넥터 생성·상태확인·삭제

**배운 점**

- **Kafka Connect는 커넥터 설정을 REST API로 관리**
  - `POST http://localhost:8083/connectors`에 JSON으로 커넥터 이름 + config를 보내면 등록·기동됨
  - 오늘 등록한 sink 커넥터 예시:
    ```json
    {
      "name": "file-sink-test",
      "config": {
        "topics": "test",
        "connector.class": "org.apache.kafka.connect.file.FileStreamSinkConnector",
        "tasks.max": 1,
        "file": "/tmp/connect-test-data.txt"
      }
    }
    ```
  - `topics`(소비할 토픽)와 `connector.class`(사용할 커넥터 구현체)가 핵심 필드 — `FileStreamSinkConnector`는 별도 플러그인 설치 없이 Kafka 배포판에 기본 포함되어 있어 바로 테스트 가능
  - `GET /connectors/{name}/status`로 커넥터/태스크 상태(RUNNING/FAILED 등) 확인, `DELETE /connectors/{name}`으로 제거 — 커넥터 재설정 없이 라이프사이클을 REST로만 다룰 수 있음

- **distributed mode의 워커 설정(`connect-distributed.properties`)이 곧 클러스터 구성**
  - `bootstrap.servers=my-kafka:9092`로 어느 브로커에 붙을지 지정
  - `group.id=connect-cluster`로 커넥트 워커들을 하나의 클러스터로 묶음 — 같은 group.id를 쓰는 워커 여러 대를 띄우면 태스크가 자동 분산/재조정됨
  - 커넥터 설정 자체(`config.storage.topic`), 오프셋(`offset.storage.topic`), 상태(`status.storage.topic`)를 전부 내부 Kafka 토픽에 저장 — 워커가 죽었다 다시 떠도 이 토픽들에서 상태를 복원하므로 별도 외부 저장소가 필요 없음
  - `key.converter`/`value.converter`를 `StringConverter`로 맞춰서, `test` 토픽에 들어있는 평문 메시지를 그대로 파일에 한 줄씩 옮겨쓰도록 구성

- **Sink 커넥터의 동작 방식**
  - Source 커넥터(외부 → Kafka)와 반대로, Sink 커넥터는 Kafka 토픽(`test`)을 컨슈머처럼 구독해서 지정한 목적지(`/tmp/connect-test-data.txt`)로 계속 흘려보내는 역할
  - 별도 컨슈머 애플리케이션(`SimpleConsumer` 등)을 직접 작성하지 않아도, 설정만으로 "토픽 → 파일" 파이프라인을 구성할 수 있다는 게 Connect의 핵심 가치임을 체감
