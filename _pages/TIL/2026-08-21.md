**배운 점**

- **Elastic Stack 기본 개념**
  - ES/Logstash/Kibana/Beats 각각의 역할과, 왜 "ELK"에서 "Elastic Stack"으로 이름이 바뀌었는지
  - RDB ↔ Elasticsearch 대응 관계 (Database→Index, Row→Document 등), 7.x부터 Type이 사실상 사라진 것
  - HTTP 메서드(GET/PUT/POST/DELETE) ↔ CRUD 매핑

- **Logstash 7.3.2가 최신 JDK에서 안 뜨는 문제**
  - Logstash는 Elasticsearch와 달리 자체 JDK를 번들하지 않고 시스템 `JAVA_HOME`을 사용 (LS_JAVA_HOME은 이후 버전에 추가된 기능)
  - JDK 25(시스템 기본값)에서 두 단계로 실패: (1) `config/jvm.options`의 `-XX:+UseConcMarkSweepGC`가 JDK14+에서 제거된 옵션이라 VM 자체가 안 뜸 (2) 그 문제를 넘겨도, 내부 JRuby 9.2.7.0(2019년산)이 JDK16+의 강화된 모듈 시스템(JPMS)에서 리플렉션 접근이 막혀 `IllegalCallerException` 발생
  - 해결: `brew install --cask temurin@11`로 JDK 11을 별도 설치하고, 실행 시에만 `JAVA_HOME`을 그 경로로 지정하는 래퍼 스크립트(`run-logstash.sh`)를 만들어 우회. 시스템 전역 JAVA_HOME은 건드리지 않아서 다른 프로젝트(Gradle 빌드 등)에 영향 없음

- **Homebrew `--cask`**
  - `.pkg`/`.dmg`처럼 macOS 설치 프로그램 형태로 배포되는 패키지(GUI 앱, JDK 등)는 formula가 아니라 cask로 설치 — 그래서 설치 시 `sudo` 권한이 필요했던 것

- **Kafka 스크립트를 `bin/` 안에서 실행할 때**
  - `bin/kafka-server-start.sh config/server.properties`처럼 config 경로가 스크립트 실행 시점의 현재 디렉토리(cwd) 기준 상대경로라, `bin/` 안에서 실행할 땐 `../config/...`로 바꿔줘야 함

- **Elasticsearch REST API 실습 중 겪은 삽질**
  - `PUT /{index}/_doc/{id}`는 완전 교체, `POST /{index}/_update/{id}`는 병합(merge) — 이 둘을 헷갈려서(Method/URL을 안 바꾸고 이전 요청 재사용) 문서에 의도치 않은 중첩 필드가 남거나 필드가 날아가는 걸 직접 경험
  - `_update`의 `doc`은 병합이라 없는 필드는 추가, 있는 필드는 덮어씀 — 하지만 필요없는 필드를 자동으로 지워주지는 않음(불필요한 필드 정리하려면 명시적으로 삭제하거나 문서를 통째로 다시 만들어야 함)
  - `_cat` API(`GET /_cat/nodes?v`, `GET /_cat/indices?v`)는 JSON이 아니라 사람이 읽기 편한 텍스트 표로 응답
  - 단일 노드 클러스터에서 인덱스 상태가 `yellow`인 건 정상 — 레플리카(`rep`)를 배치할 다른 노드가 없어서 미할당 상태일 뿐, 프라이머리 샤드는 정상
  - Painless 스크립트에서 `ctx.op`으로 업데이트 요청의 최종 동작(`delete`/`none`)을 조건부로 제어 가능
