**배운 점**

- **`geoip` 필터**
  - 사설 IP(`192.168.x.x`)와 예약 대역(TEST-NET, `203.0.113.x`/`198.51.100.x`)은 MaxMind DB에 위치 정보가 없어서 `_geoip_lookup_failure` 태그가 붙는 게 정상 동작 — 버그가 아님
  - 공인 IP(`8.8.8.8`→US, `1.1.1.1`→호주)는 정상적으로 country/lat/lon/timezone까지 채워짐. `1.1.1.1`이 호주로 나오는 건 Cloudflare가 이 대역을 APNIC(호주 소재)에서 할당받았기 때문 — MaxMind 데이터가 정확한 것

- **`elasticsearch` output, time-based index**
  - `index => "weblog-%{+YYYY.MM.dd}"`처럼 `%{+포맷}` 문법으로 이벤트의 `@timestamp`를 인덱스 이름에 끼워 넣을 수 있음 — Phase 4에서 봤던 `logstash-2015.05.18` 같은 날짜별 인덱스 패턴을 직접 만든 것
  - Elasticsearch가 꺼져 있으면 Logstash는 에러로 죽지 않고 `HostUnreachableError` WARN을 반복하며 재시도 큐에 쌓아둠 — ES를 다시 띄우면 자동으로 이어서 인덱싱됨

- **Filebeat**
  - `filebeat.inputs`(파일 경로) + `output.logstash`(대상 호스트:포트) 두 부분만 설정하면 최소 동작 가능
  - Filebeat → Logstash `beats` input → 기존 grok/geoip 필터·elasticsearch output 그대로 재사용 가능 — 데이터 수집 경로(direct file read vs Filebeat 경유)만 바뀌고 파이프라인 뒷단은 그대로 재사용된다는 걸 직접 확인
  - Logstash를 먼저 띄워 5044 포트가 리스닝 상태가 된 뒤에 Filebeat를 실행해야 함(순서 상관은 없지만 에러 로그를 피하려면 이 순서가 깔끔)
