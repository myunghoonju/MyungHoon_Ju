**배운 점**

- **기본 컨슈머 구조 (SimpleConsumer)**
  - `GROUP_ID_CONFIG`로 컨슈머 그룹을 지정하면, 같은 그룹의 컨슈머들이 토픽 파티션을 나눠 가짐(컨슈머 그룹)
  - `consumer.poll(Duration)` 루프로 레코드를 가져오는 게 기본 패턴, `KafkaConsumer`는 try-with-resources로 자동 close
  - 종료 시그널에서 `consumer.wakeup()`을 호출해 poll을 깨우고 `WakeupException`으로 루프를 빠져나가는 graceful shutdown 패턴
    ```java
    Runtime.getRuntime().addShutdownHook(new Thread(consumer::wakeup));
    ...
    } catch (WakeupException e) {
      log.info("consumer shutting down");
    }
    ```

- **커밋: 자동 vs 수동(동기/비동기)**
  - `ENABLE_AUTO_COMMIT_CONFIG` 기본값 true → poll 호출 시점에 주기적으로 오프셋이 자동 커밋됨. 레코드 처리 전에 커밋돼버릴 수 있어 장애 시 유실 가능성 있음
  - 수동 커밋(`false`)으로 바꾸고 레코드 처리가 끝난 뒤 명시적으로 커밋하는 게 더 안전
  - `commitSync()`: 브로커 응답까지 블로킹, 실패 시 예외로 감지하고 재시도하기 쉽지만 처리량 저하
  - `commitAsync(callback)`: 논블로킹, 콜백으로 성공/실패만 통보받음. 순서를 보장하지 않아 최신 오프셋보다 이전 오프셋 커밋이 늦게 실패하면 꼬일 수 있어 재시도 전략을 직접 관리해야 함

- **리밸런스 리스너 (ConsumerRebalanceListener)**
  - `consumer.subscribe(topics, listener)` 형태로 등록
  - `onPartitionsRevoked(partitions)`: 파티션을 뺏기기 직전에 호출 → 이 시점에 커밋 등 정리 작업을 해야 리밸런싱 중 유실/중복을 줄일 수 있음
  - `onPartitionsAssigned(partitions)`: 새 파티션이 할당된 직후 호출 → 시작 오프셋 세팅 등 초기화 가능
  - 즉, 리밸런싱 시점의 커밋 타이밍을 컨트롤할 수 있는 훅

- **정리**
  - producer/consumer 클래스를 각각 `producer`, `consumer` 패키지로 분리해서 정리
